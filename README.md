HydraBox is the official client of the Hydra self-hosted stack. Its primary
integration contract is [HydraBox Subscription v1](docs/hydrabox-subscription-v1.md),
generated by [HYDRA Ultimate](https://github.com/gr33nimax/HYDRA-ULTIMATE) and
executed by [HydraCore](https://github.com/gr33nimax/hydracore). Complete native
sing-box JSON documents are preserved losslessly, so protocols and fields added
by HydraCore do not require a matching Flutter envelope schema.

Manual and legacy imports remain available for migration and interoperability.
They are compatibility surfaces, not a second product direction: the Hydra
ecosystem is designed around one encrypted subscription from the self-hosted
server to the client.

The app does not provide VPN servers. It is a client for subscriptions and configurations that you own or are allowed to use.

## Status

HydraBox is in public beta. Android is the supported production target. Other
Flutter platform folders may exist in the repository, but they are not release
targets yet.

## Hydra ecosystem

```text
HYDRA Ultimate  ->  encrypted subscription  ->  HydraBox  ->  HydraCore
self-hosted server                               client        runtime
```

- [HYDRA Ultimate](https://github.com/gr33nimax/HYDRA-ULTIMATE) deploys and
  manages the self-hosted server and produces the subscription.
- HydraBox imports, stores, refreshes, and activates the subscription.
- [HydraCore](https://github.com/gr33nimax/hydracore) validates and executes
  the native networking configuration.

Hydra is not a hosted VPN provider. You control the server and the subscription.

## Quick start

1. Deploy HYDRA Ultimate on a server you control.
2. Create or copy its encrypted HydraBox subscription URL or QR code.
3. Install HydraBox from [GitHub Releases](https://github.com/gr33nimax/hydrabox/releases).
4. Import the subscription in HydraBox and connect.

The subscription decryption key is carried only in the URL fragment and is not
sent to the subscription server. See the
[Subscription v1 specification](docs/hydrabox-subscription-v1.md) for the exact
trust and validation model.

## Features

- Android VPN TUN mode powered by HydraCore.
- Versioned HydraBox Subscription v1 with explicit profiles, an opaque native
  runtime document, lossless future-protocol fields, and JWE A256GCM transport.
- Local mixed proxy inbound for apps or devices that use HTTP/SOCKS manually.
- Subscription import from URL, QR code, local file, clipboard, and deep links.
- Deep link handlers for `hydrabox://`, the legacy `etonify://` and
  `meowvpn://` aliases, `happ://add`, `happ://crypt*`, and
  `sing-box://import-remote-profile`.
- Happ link decryptor for `crypt`, `crypt2`, `crypt3`, `crypt4`, and `crypt5` links.
- Happ subscription import with explicit HWID consent when a provider requires it.
- Subscription refresh, reparse, usage display, expiration display, and safe handling of invalid refresh results.
- Proxy list with country flags, latency, source-order sorting, latency/name/country sorting, URL-test, and quick server switching.
- Split tunneling using Android VPN app allow/disallow rules plus sing-box routing fallback.
- DNS presets and custom DNS resolver support, including UDP, TCP, DoT, DoH, and device DNS modes.
- Smart Routing rule sets and a locally compiled AdGuard DNS filter.
- Traffic dashboard with live speed, session totals, active profile, active proxy, and a lightweight graph.
- Optional GitHub release update center with ABI-aware APK selection and
  download progress; it stays disabled until a HydraBox release source is
  configured by the distributor.
- Runtime logs, diagnostics, memory cleanup hooks, and redaction for known sensitive values.
- RU/EN app localization, with more user-facing translations planned.

## Development

Requirements:

- Flutter 3.44.0 or newer with Dart `>=3.11.4`.
- Android SDK 36.
- JDK 21 can be used to run Gradle, while Android bytecode targets remain Java 17 for current AGP compatibility.

Common commands:

```powershell
python -B scripts/fetch_libbox.py
flutter pub get
flutter gen-l10n
flutter analyze
flutter test
```

Local release APK for device testing:

```powershell
$env:MEOW_ALLOW_DEBUG_RELEASE_SIGNING='true'
flutter build apk --release
adb install -r build\app\outputs\flutter-apk\app-release.apk
```

For public distribution, create a real release keystore and `android/key.properties`. That file is intentionally ignored by Git.

## Notes

- Production focus is Android.
- HydraCore currently hydrates the compatibility artifact `libbox.aar` from
  the pinned
  [`gr33nimax/hydracore`](https://github.com/gr33nimax/hydracore/tree/extended-integration)
  prerelease. Its source commit, release URL, SHA-256 and build provenance are
  documented under `android/app/libs` and verified before every Android build.
- Historical identifiers such as `com.etonify.meow_client`, `meow_client`,
  `etonify://`, and the `etonify-core` submodule path are intentionally retained
  for Keystore, storage, channel, deep-link, and authorized migration
  compatibility. The Android ID alone does not permit a differently signed APK
  to replace Etonify. See [UPSTREAM.md](UPSTREAM.md).
- Generated l10n files under `lib/l10n/generated` are part of the source tree because the app imports them directly.
- `third_party/flutter_circle_flags` is required by `pubspec.yaml` as a local path dependency.
- Third-party attribution notes are tracked in [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md).
- An inherited encrypted Happ compatibility archive may be present. Do not
  restore or ship its contents until redistribution rights have been verified;
  see [NOTICE.md](NOTICE.md).
