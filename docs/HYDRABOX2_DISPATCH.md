# Как отдавать задачи 2.0 агенту

Один блок ниже — всё, что нужно. Подставь ID задачи вместо `<TASK ID>` и отправь.
Наряд писать не надо: карточка задачи и так лежит в плане, а правила поведения —
в шаблоне. Развёрнутый наряд нужен только тогда, когда я его сам дал: это значит,
что в карточке дефект или требуется решение тимлида.

## Обычная задача — паста как есть

```
Задача: <TASK ID>.

Читать в этом порядке:
  1. docs/AGENT_DISPATCH_TEMPLATE.md — правила поведения, они обязательны.
  2. docs/HYDRABOX2_PLAN.md — карточку <TASK ID> в §6, плюс разделы, на которые она
     ссылается: §4.1 принципы, §4.2 модули, §4.3 рантайм и эффекты, §4.4 контракт,
     §4.8 инварианты, §4.9 запреты commonMain, §10 сквозные запреты, §12 реестр
     решений.
  3. docs/HYDRABOX2_TASK_LEDGER.md — проверить, что предшественники по §7 выполнены.

Предпосылки проверяй ПО КОДУ и по ledger, не по полю STATUS в карточке. Истина о
выполненном — ledger и git log.

Решения из §12 не переспрашивай и не пересматривай: они приняты. Пункты §13
отложены и основанием для BLOCKED быть не могут. Если задача требует решения,
которого в §12 нет и которое карточка относит к тимлиду — подготовь анализ
вариантов по коду и остановись, не коммитя.

Проверки на устройстве не проводятся до фазы G. Host-side валидация из карточки
обязательна и должна быть зелёной ДО коммита. Красные тесты, оставленные
предшественником, чинить отдельным ПЕРВЫМ коммитом; ожидания не ослаблять.

Границы карточки соблюдать буквально. Мёртвый код и дефекты вне границ — строкой в
отчёт, не править.

Коммит: явные пути, трейлер Task: <TASK ID>. git add -A и git commit -a запрещены.
Последний шаг — строка в docs/HYDRABOX2_TASK_LEDGER.md.

Отчёт по форме шаблона: RESULT, RULES APPLIED, PRECONDITIONS CHECKED,
DEVICE CHECKS DEFERRED, плюс всё, что нашёл вне задачи.
```

## Цепочка задач — когда хочешь отдать несколько подряд

Добавь к блоку выше:

```
После отчёта переходи к следующей задаче по §7 сам, не дожидаясь подтверждения.
Порядок: <ID> -> <ID> -> <ID>. Остановись перед задачей, у которой в карточке
критерий готовности требует решения тимлида, и перед первой задачей фазы G.
```

Одновременно один агент в одном worktree. Параллелить можно только ветки,
помеченные независимыми в §7 — фазу D, фазу E, подготовку Windows (`H2-F01`,
`H2-F02`), `H2-C05` — и только в разных worktree.

## Когда агент сообщает BLOCKED

Не пересылай мне отчёт сразу. Сначала посмотри на одну вещь: назвал ли агент
конкретный символ, файл и строку карточки, которая этого требует. Если назвал —
присылай, это моя работа. Если написал общо («требует расширения scope», «зависит
от предшественника») без конкретики — верни ему одну строку:

```
Назови файл, символ и строку карточки, из которой следует блокировка. Проверь
сначала правила самостоятельного разрешения в docs/AGENT_DISPATCH_TEMPLATE.md.
```

## Что присылать мне

Отчёт агента целиком, без пересказа. Если в отчёте есть строка «остановился, нужно
решение тимлида» — этого достаточно, дальше моя часть.
