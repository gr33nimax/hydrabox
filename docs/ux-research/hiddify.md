# Hiddify (Flutter, sing-box) — UX-логика и что перенять в HydraBox

Источники (только чтение): README и дерево `lib/` репозитория hiddify-app, ключевые
UI-файлы (connection, proxies, profile, add profile, per-app proxy, logs) и
`assets/translations/en.i18n.json`. Сырьё — в `docs/ux-research/.raw/`.

## Как устроен их UX (паттерны, не код)

**Подключение.** Состояние соединения — sealed-тип из четырёх вариантов:
`Disconnected(failure?) / Connecting / Connected / Disconnecting`. Вся кнопка
(подпись, цвет, enabled, анимация) выводится из него одним исчерпывающим switch —
промежуточные состояния физически не могут отрендериться как «подключено».
Во время `Connecting/Disconnecting` кнопка заблокирована, а вызовы connect
защищены троттлингом: повторные тапы игнорируются.
Есть частный случай «подключено, но пинга нет (0 или >65 c)» — кнопка
показывает «Connecting…» жёлтым и не анимируется.
Опции изменились → кнопка превращается в **Reconnect** (иной цвет), а не в
Disconnect: перезапуск ядра — отдельное, названное действие. Смена активного
профиля вызывает reconnect, а не тихое переключение.
Подключиться без профиля нельзя: диалог «Choose a profile» + «Show me how»
+ сразу открывается добавление профиля. Смена состояния даёт haptic-отклик.

**Серверы и пинг.** Экран прокси: список/грид, сортировка (по задержке, по имени),
FAB «Test delay» = тест всех и выбор лучшего, у активного прокси — отдельный
перетест по тапу. Три визуальных состояния пинга: shimmer = «тестируется»,
число ms, слово Timeout красным; всё с `Semantics`-подписью. Пустой список —
«No proxies available», ошибка — одна человеческая строка, не трейс.

**Профили и подписки.** У отдалённого профиля карточка: % остатка трафика и
прогресс-бар с цветом (красный <25 %, оранжевый <45 %, зелёный дальше),
остаток дней (`∞` при >365), состояние «Out of quota», ссылки «Провайдер» и
«Поддержка» с иконкой по домену. Действия профиля: Update, Share → {URL в буфер,
QR, JSON в буфер}, Delete. Удаление — не undo, а подтверждающий диалог.
Добавление — один bottom-sheet: буфер / файл / QR / вручную + свободные подписки
по региону, валидация имени и URL, авто-обновление с интервалом. Deep link
открывает тот же sheet с подставленным URL.
Авто-обновление: планировщик 15 мин, per-profile `updateInterval`, guard по
`lastUpdate` («too soon»), тост с **именем** профиля при успехе и при провале,
пропуск работы до завершения онбординга.

**Надёжность.** Все сбои типизированы и показываются через `present()` —
человекочитаемо и с действием: missing privilege → «нужна перезагрузка с правами
администратора или другой service mode»; WARP/Psiphon без согласия → «нужна
лицензия». Перед подключением с экспериментальными опциями — разовое
уведомление (opt-in, «Don't show again»). Настройки: service mode, strict route,
reset VPN-профиля, log level, интервалы тестов, шаринг профиля в LAN
(ссылка + QR), статистика live/total, скорость в уведомлении. Закрытие окна —
«Hide or exit? Ask each time / Remember my choice», трей-иконка открывает окно
или меню. Онбординг — отдельные страницы (intro, согласие с terms), пустые
экраны всегда с кнопкой действия.

**Чего у них НЕТ**: kill-switch и always-on/auto-reconnect при смене сети
отсутствуют — полагаются на ОС и `strictRoute`. Undo после удаления тоже нет:
только confirm.

## Что перенять в HydraBox (по влиянию)

### Высокое
1. **Sealed-состояние соединения** (`disconnected(failure?) / connecting /
   connected / disconnecting`) как единственный источник для подписи, цвета,
   `enabled` кнопки. Плюс троттлинг действий: пока идёт switching — тап
   игнорируется, а не ставит вторую попытку в очередь. Убирает «кнопка врёт».
2. **Разделить Disconnect и Reconnect.** Если изменились опции/профиль —
   кнопка называется Reconnect и перезапускает ядро. Ни один перезапуск не
   происходит молча.
3. **Никогда не подключаться без активного профиля**: диалог-объяснение +
   сразу переход к добавлению. Пустой экран — не тупик.
4. **Типизированные ошибки → текст + действие.** Ветки: нет прав, нет или
   невалиден конфиг, таймаут, ядро не запущено. Никаких «Unexpected error»
   без следующего шага.
5. **Пинг как полноценная часть UI**: задержка на сервер, «тест всех и выбрать
   лучший», состояния testing / timeout / значение.
6. **Подписка обязана показывать здоровье**: остаток трафика и дней с цветовым
   порогом и явным «квота кончилась», дата последнего обновления, интервал
   обновления с guard от повторного запуска, тост с именем профиля при
   успехе/провале обновления (не общий «ошибка»).

### Среднее
7. Единый экран добавления (буфер / файл / QR / вручную) с валидацией и
   подтверждением для deep link с показом хоста-источника.
8. Удаление — confirm-диалог с именем объекта; undo оставить только для
   обратимых одномоментных действий (переключение сервера), не для удаления.
9. Предупреждения перед необратимым: импорт настроек/правил «перезапишет всё»,
   открытие ссылки на незнакомый домен, включение экспериментальных опций.
10. Диагностика на виду: отдаваемые логи ядра и приложения, уровень логов,
    сброс туннеля.
11. Поведение при закрытии окна: «Ask each time / Remember my choice» + трей.

### Низкое
12. Haptics, анимация цвета кнопки, сортировка списка, иконки соцсетей —
    приятно, но на надёжность не влияет.
13. **Добавить то, чего у Hiddify нет**: kill-switch, always-on, авто-реконнект
    при смене сети и после пробуждения, индикатор «сеть сменилась,
    переподключаюсь» — их слепая зона и наш шанс.

**Итог: причина одной строкой** — Hiddify выигрывает тем, что состояние, ошибка
и результат действия всегда названы и имеют следующий шаг. **Что делать:** начать с пунктов 1–4 (кнопка, reconnect,
отсутствие профиля, типизированные ошибки) — это даёт максимум стабильности и
предсказуемости за минимум изменений.
