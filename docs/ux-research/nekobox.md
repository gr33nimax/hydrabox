# NekoBox for Android: реальные флоу и что перенять

Источник: `starifly/NekoBoxForAndroid@main`, скачанные файлы в `docs/ux-research/.raw/`. Ниже — поведение, не имена классов.

## Модель

Профиль всегда принадлежит группе (`groupId`), у него есть `userOrder`, `status`, `ping`, `error`, `dirty`. Группы: BASIC (ручная), SUBSCRIPTION, служебная UNGROUPED (одна, скрывается из списка, если пуста и групп больше одной). Выбранный профиль — **одна глобальная настройка** (`selectedProxy`), не per-group. Смена выбора при запущенном сервисе сразу перезапускает его.

## Импорт: один парсер на все входы

Пять путей: QR, буфер, файл (включая `.zip` с несколькими конфигами), ручное создание, подписка. Четыре из пяти идут в один эвристический мультипарсер: raw-ссылки, base64-блок, Clash YAML, sing-box JSON, WireGuard ini. Поведение:

- Импорт кладёт профили **в выбранную группу**, переключает UI на неё и показывает «Добавлено N» — не создаёт группу молча.
- Если текст оказался ссылкой на подписку, парсер бросает отдельное исключение, и UI открывает **форму группы-подписки** с заполненными типом, ссылкой и именем (имя тянется из `profile-title` → `content-disposition` → заголовка, таймаут 5 с), `autoUpdate=false`. Первый апдейт — только после подтверждения.
- QR: экран закрывается после первого распознавания; ошибка — тост, не краш; мультискан копит счётчик.
- Ошибка парсинга всегда доходит до пользователя текстом, молчания нет.

## Обновление подписки — самый ценный блок

Апдейт не перезаливает группу, а **диффит по имени профиля**:

1. Дубли имён внутри подписки переименовываются (`name (1)`, `name (2)`) — ключ сопоставления гарантированно уникален.
2. Опционально regex-фильтр include/exclude и дедупликация по содержимому+классу протокола; список дублей отдаётся в отчёте.
3. Сопоставление с существующими по имени: пропавшие → на удаление; совпавшие → сравнение содержимого. Отдельная ветка: содержимое то же, но `userOrder` другой → тихое переупорядочивание (не «обновление»). Иначе — `Ignored`.
4. **При замене профиля переносятся пользовательские оверрайды** (`customOutboundJson`/`customConfigJson`) — правки поверх подписки не затираются.
5. `userOrder` присваивается по порядку в новой подписке → порядок источника сохраняется.
6. Пустой результат — ошибка, а не пустая группа.
7. Опция force-resolve: DNS-резолв адресов, перезапись `serverAddress` и подстановка SNI, если пуст; 5 потоков, прогресс в общую карту → прогресс-бар на карточке группы.
8. Защита от параллельного апдейта (synchronized set): повторный запуск отменяется. Флаг снимается всегда, в т.ч. при ошибке.
9. `lastUpdated` ставится только после успеха.
10. Апдейт по `http://` или при `updateWhenConnectedOnly` без соединения → диалог подтверждения.
11. Группа с автогенерированным именем получает имя от сервера.
12. Один канал результата: `changed, added, updated, deleted, duplicate, byUser` — тост показывается только при ручном апдейте.
13. Строки не пересоздаются: совпавшие профили обновляются на месте, id сохраняются — выбранный профиль, его трафик и статистика не теряются при апдейте.

**Топ-1 к перенятию:** дельта-апдейт по ключу имени + сохранение оверрайдов + честный отчёт + идемпотентность (повтор без изменений = no-op) + один апдейт на группу.

## Список: порядок и тесты

Порядок — свойство группы: ORIGIN (ручной), BY_NAME, BY_DELAY (недоступные в конец). Drag-and-drop пишет порядок всем затронутым и **только по завершении жеста**, а не на каждый move.

Тесты: TCP-ping (connect + таймаут 3 с) и url-test, ограниченный параллелизм, глобальный флаг «тест уже идёт» (второй запуск невозможен). Результат пишется в профиль и в БД; при отмене **частичный результат сохраняется**. `status`: 0 неизвестно, 1 ок, 2 известная ошибка (timeout/refused/unreachable/domain not found — человеческим текстом), 3 сырая ошибка; детали по тапу показываются только для 3. Есть отдельные «очистить результаты теста» и «очистить трафик». Per-group теста нет: карточка группы показывает агрегат (трафик/остаток подписки), а пинг живёт на профилях — тестируется группа целиком, сортировка применяется к её списку.

## Удаление с Undo

Один recycle-bin на список. Swipe → элемент исчезает из UI сразу, попадает в корзину, показывается Snackbar «Удалено N» с UNDO; восстановление возвращает на исходную позицию. **Реальная запись в БД — только при dismiss Snackbar**, и только если dismiss не вызван нажатием Action. Удаление второго элемента перезапускает Snackbar и растит корзину, commit объединяет всё. Корзина коммитится принудительно при добавлении/обновлении/уходе с экрана — отложенное удаление не зависает. Swipe и drag запрещены во время апдейта группы; удаление выбранного профиля сбрасывает выбор; удаление группы чистит её профили.

**Топ-2 к перенятию:** soft-delete + Undo + commit-на-dismiss, а не мгновенное удаление из БД.

## Правка профиля и группы

Схема `init()/serialize()` поверх кэш-хранилища и флага `dirty`: все правки идут в кэш, в БД попадают только по «Apply». Ключи кэша совпадают с именами полей — один декларативный маппинг. Уход назад с несохранёнными правками → диалог «сохранить / выйти / отмена». Видимость полей — функция значений: тип сети переключает целые категории и меняет заголовки, `security=tls` открывает TLS/ECH, режим mux переключает набор mux-полей (скрытие, не удаление). Правка активного профиля останавливает сервис. Пароль маскируется, порт валидируется маской, интервал автообновления — ≥15, DNS — с тостом об ошибке. При смене ссылки подписки сбрасывается `subscriptionUserinfo`, иначе показывался бы чужой трафик.

**Топ-3 к перенятию:** изолированный кэш + явный dirty + диалог несохранённого; видимость полей от значений; сброс производных данных при смене источника.

## Шаринг

Пункты меню шаринга **скрываются**, если ссылки нет (нет стандартной ссылки / нет ссылки вообще) — нерабочих кнопок не бывает. QR строится из ссылки; ошибка генерации → snackbar и закрытие диалога, не краш. Для группы: QR universal-link, копирование в буфер, экспорт списка ссылок в файл, экспорт universal-link. Копирование возвращает признак успеха → разные тосты успех/ошибка.

## Приоритет внедрения

1. Дельта-апдейт подписки (оверрайды, отчёт, идемпотентность, один апдейт).
2. Удаление с Undo и commit-на-dismiss.
3. Единый парсер импорта; «подписка → сначала форма»; импорт в текущую группу с навигацией.
4. Модель status/error с человеческими сообщениями; запрет параллельных тестов; частичный результат при отмене.
5. Кэш правок + dirty + диалог несохранённого; видимость полей от значений; сброс производных данных.
6. Порядок группы (origin/name/delay) в БД, запись по завершении жеста.
7. Блокировка swipe/drag во время апдейта; сброс выбранного при удалении.
8. Шаринг: скрывать нерабочее, проверять результат буфера/файла.
9. Прогресс апдейта на карточке группы + confirm при апдейте без соединения.
