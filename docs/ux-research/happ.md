# Happ (happ.su / happ.info) — UX-логика и что перенять в HydraBox

Источники: `docs/ux-research/.raw/` (happ-home, happ-llms.txt, `md/*` — GitBook-доки, у каждой страницы есть markdown-версия по `.md` в конце URL; индекс — `/main/llms.txt`).
Happ закрытый: исходников нет, разбор по публичным докам и скриншотам. Поведение UI выведено из описаний; живьём приложение не запускалось — это ограничение, а не проверенный факт.

## Ранжировано по влиянию

### 1. Подписка как канал управления приложением (главное)
Провайдер задаёт UX не через экран настроек, а через метаданные подписки. Доставка — **двумя равнозначными путями**: HTTP-заголовки ответа ИЛИ строки-комментарии `#key: value` в теле подписки (`profile-title`, `subscription-userinfo: upload=..;download=..;total=..;expire=..`, `support-url`, `profile-web-page-url`, `announce`, `sub-info-text/color/button-*`, `sub-expire`, `fallback-url`, `new-url`, `new-domain`, `notification-subs-expire`, `subscriptions-sort-type`, `ping-result`, `subscriptions-collapse`…). Одно и то же значение работает в любом панельном формате.
**Перенять:** спецификация «subscription metadata v1» с двумя транспортами, версионированием и явным списком ключей. Провайдер меняет серверы/домен/текст — пользователь ничего не перенастраивает. Это и стабильность, и предсказуемость разом.

### 2. Самолечение подписки
`fallback-url` включается при ошибке 300–599 или таймауте (по умолчанию 9 с, настраивается 5–15 с); `new-url`/`new-domain` мигрируют адрес у всех клиентов; если запрос не ушёл из-за блокировки — **повтор после установления VPN**.
**Перенять:** бэкап-URL + авто-миграция домена + отложенный ретрай через туннель. Дёшево, убирает целый класс «перестало обновляться».

### 3. Честный пинг вместо одной цифры
Три метода: ICMP (требует разорвать туннель), TCP (может мерить ближайший CDN, не сервер), via-proxy (полный путь + TLS, «самый показательный»). Пользователь выбирает отображение: `ms` или иконка (зелёная галочка / красная!). Есть «Ping on Launch» (проверка всех серверов при открытии), `proxy-ping-timeout` 5–15 с (дефолт 7), режимы `default/double/keepalive`.
**Перенять:** не выдавать TCP-пинг за задержку до сервера; подписывать метод; авто-прогон при старте; иконка-статус как альтернатива цифрам.

### 4. Атомарное обновление роутинга
Новые geofile качаются в фоне, пока ядро работает **на старых правилах**; замена — только после полной загрузки. Смена настроек роутинга сохраняется в БД и применяется лишь при переподключении (явный «Reconnect»). Ошибка загрузки: стоп через 3 мин, красный «!» у профиля, авто-снятие после успеха/удаления.
**Перенять:** download-then-swap и deferred-apply. Никогда не ломать текущее соединение обновлением.

### 5. Добавление конфига: 3 способа × 3 транспорта
Ручной ввод, ссылки (`vless/vmess/ss/trojan/socks/hy2`), подписка (обычная и **зашифрованная `happ://crypt5/`** — URL и настройки скрыты, редактирование/шаринг запрещены). Транспорт: буфер обмена, QR, deeplink. Плюс `hide-settings`, HWID-ссылки (привязка к устройству) и limited links (лимит установок, сервер отдаёт «администратор ограничил доступ»).
**Перенять:** deeplink + QR + клипборд в одном экране; шифрованная подписка как первоклассный тип; осмысленный отказ при лимите.

### 6. Плотная строка сервера, один жест
Флаг-эмодзи в начале имени → иконка сервера (после флага — только текст); `serverDescription` (≤30 симв.) заменяет подпись «VMess/VLESS»; `title` ≤30 симв.; строка статуса: использовано/всего трафика + дата; свайп вправо → панель действий (пинг, share: clipboard / QR / JSON).
**Перенять:** свайп-панель и флаг-иконка из имени. Минимум экранов, максимум смысла.

### 7. Понятные ошибки и сроки
Отдельные тексты: «буфер пуст», «неверный deeplink», «unknown content type», «timeout while adding subscription (9 с)». Истечение: `sub-expire` показывает сообщение только за ≤3 дня, кнопка всегда «Renew»; пуш 1 раз в день 3 дня.
**Перенять:** словарь ошибок с причиной, а не «что-то пошло не так»; правило «показывать только когда пора».

### 8. Онбординг TV/первого запуска
При первом старте — передача подписки с телефона по QR через LAN, при неудаче — через интернет; плюс web-import с кодом (`tv.happ.su`). Роутинг — на уровне подписки (свой набор правил и профилей, каскадное удаление), JSON-подписка в restricted-режиме (0–1 профиль, тумблер залочен) — против рассинхрона настроек и метаданных.
**Перенять:** QR-трансфер с фолбэком, каскадная очистка ресурсов, явный restricted-режим вместо «тихо перезапишем».

## Мелочи, но дешёвые
LAN-шаринг показывает `Current IP`, `SOCKS5 Port`, `HTTP Port` явно. «Remote DNS» переименован в **Tunnel DNS** (точнее по смыслу). Geo-файлы предустановлены — работает сразу после установки. `no-limit-enabled` как ручка RAM для стабильности ядра. Дефолт фрагментации включён.

## Итог одной строкой
Причина: Happ держит UX **в данных подписки**, а не в коде экранов; что делать: ввести версионированный subscription-metadata (headers + `#`-комментарии) с fallback-URL, атомарным apply и честным пингом.
