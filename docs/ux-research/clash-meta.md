# Clash Meta for Android (CMFA) + FlClash — UX-логика и что перенять в HydraBox

Источники (только чтение): README, дерево репо и ключевые UI/сервис-файлы
`MetaCubeX/ClashMetaForAndroid` (Kotlin/View-биндинг) и `chen08209/FlClash`
(Flutter, Material You) — `default_branch=main` у обоих (проверено через API),
release notes обеих за последний год. Сырьё — `docs/ux-research/.raw/`
(`cma/`, `flclash/`, `*-tree.json`, `*-releases.json`).

## Как устроен их UX (паттерны, не код)

**Домашний экран / подключение.** CMFA: три карточки — статус (Stopped/Stopped→
«Tap to start» / Running + «Forwarded N»), Proxy (подтекст = текущий режим
Rule/Global/Direct, видна только когда запущено), Profile («Activated: имя» /
«Not selected»); ниже — ссылки Providers (только если запущено и есть провайдеры),
Logs, Settings, Help, About. Всё связано с состоянием ядра, ничего не рендерится
оптимистично. Старт без профиля → тост «no profile selected» с действием
«Profiles». Смена режима в списке прокси — это **сессионный override** с подсказкой
«valid only for current session», сбрасывается при стопе; постоянный — в настройках.
FlClash: FAB play/pause с морфингом и счётчиком времени работы (скрыт, если нет
профилей), рядом отдельный индикатор ядра connected/connecting/disconnected —
спиннер появляется только если connecting длится >600 мс (анти-мерцание), тап по
индикатору = подтверждённый force-restart; режим — radio-карточка или сегмент-таб.

**Профили/подписки.** CMFA-карточка: имя, тип (или «Unsaved» для pending),
использовано, всего, срок (поля с нулём/пустотой скрыты), «N ago» от updatedAt,
пересчитывается живьём; меню Activate/Update/Edit/Duplicate/Delete; «Update all» —
только если есть URL-профили, с вращающимся спиннером. Авто-обновление — AlarmManager,
минимум 15 мин, перепланируется на boot/замену пакета/смену времени и таймзоны,
интервал считается от mtime файла (не сбрасывается при каждом запуске); шапка
`subscription-userinfo` обновляет трафик/срок/интервал. Редактор: только http(s),
непустое имя, ≥15 мин, подтверждение «выйти без сохранения — всё потеряется».
Прогресс загрузки фазами: fetch config → fetch provider (детерминированный) →
verify. FlClash: карточка подписки (used/total + срок, адаптивно скрывает срок,
если не влезает) + шит с деталями, in-app редактор файла и YAML-превью, «profile
has update», удаление активного → автопереключение на первый.

**Выбор прокси.** CMFA: табы по группам, запоминается последняя группа; плавающая
«URL Test» только для текущей группы (прячется при скролле и во время теста,
прогресс в самой кнопке); задержка числом, пусто при таймауте; сортировка
Default/Name/Delay, «exclude not selectable», плотность 1/2/3 — всё персистится.
FlClash: тип карточки min/expand, плотность tight/standard/loose, стиль иконок,
сортировка none/delay/name, per-proxy перетест, «scroll to selected», тест группы
из её заголовка; у computed-групп (url-test/fallback/load-balance) показывается
**фактически выбранный узел** и тултип «not selected»; тесты идут через пул с
лимитом параллельности, у прокси есть pending-состояние, тесты отменяются при смене
профиля; смена прокси дебаунсится по группе, оптимистично применяется и
**откатывается к прежнему выбору** при ошибке.

**Надёжность.** CMFA: сетевой callback ранжирует транспорты (wifi>ethernet>usb>bt>
cellular), для «losing» сети есть грейс-период, DNS переотправляется в ядро на любом
изменении линка и очищается при выходе; `setUnderlyingNetworks` на старых API; TUN
через VpnService.Builder (фиксированные MTU/gateway/DNS, per-app allow/deny,
allowBypass, системный прокси через случайный 127.x порт на API 29+); старт под
глобальным мьютексом с reset ядра и очисткой сессионного override; forceGc по
onTrimMemory. Уведомление — статус-поверхность: имя профиля, статично «Running» или
динамически скорость/итоги, тик 1 с **только при включённом экране**, тап → приложение.
QS-плитка (вкл/выкл + имя профиля), автозапуск с boot, динамические шорткаты,
внешние интенты и `clash://install-config`. FlClash: отдельный процесс ядра (v0.8.88)
+ «core status check and force restart»; BootGuard — запись о загрузке
(stage/failureCount/lastFailedProfile) ловит цикл падений и деградирует вместо
бесконечного рестарта; VpnManager ловит смену VPN-конфига и предлагает «Restart»
(троттлинг 10 с); пайплайн запуска — серийная очередь задач с результатом
completed/handoffToCoreRestart/failed, откат локального «running» при сбое, дебаунс
применения конфига, учёт suspend, рестарт ядра после выдачи VPN-разрешения.
Очередь сообщений: дедуп одинаковых, лимит буфера, 2 видимых на мобиле / 4 на
десктопе, error вытесняет не-error, у сообщения с действием минимум 6 с, свайп
останавливает таймеры.

**Маршрутизация/override.** CMFA: настройки TUN/access-control **заблокированы при
запущенном ядре** с явным тостом «options unavailable until Clash stopped»; override
слоты (General/DNS/Hosts…) с полным сбросом; meta-фичи (sniffer, geo-файлы, unified
delay, geodata mode); per-app allow/deny + select all/none/invert, import/export,
поиск. FlClash: whitelist/blacklist, фильтры system/no-internet, сортировка
default/name/time, «intelligent select», буфер обмена, сохранение изменений
отдельным шагом; on-demand по SSID (reorder, подсказки по location-разрешению и
battery optimization); custom overwrite + редактор правил с мультивыбором.

**Дашборд/коннекшены/логи/пустые состояния.** FlClash: из-за случайного порядка Go-map
коннекшены сортируются по трафику, чтобы список не «прыгал» между опросами (поллинг 1 с),
есть закрыть-одну/все; в requests/logs — переключатель авто-скролла, поиск, экспорт;
пустые экраны — иллюстрация + подпись + действие. CMFA: логи списком файлов с
подтверждением удаления, отдельный logcat-экран, экран AppCrashed с логами приложения,
ApkBroken.

## Что перенять в HydraBox (по влиянию)

### Высокое
1. **Ядровый статус как первоклассный UI**: отдельный индикатор состояния ядра с
   подтверждённым force-restart и анти-мерцанием (600 мс) + BootGuard-запись о
   попытке запуска (failureCount/lastProfile) с деградацией вместо рестарт-цикла.
2. **Единый источник состояния**: статус соединения/ядра определяет подпись, цвет,
   доступность и действия; неработающие опции выключаются с объяснением, а не
   игнорируются молча.
3. **Статус-поверхность на Android**: уведомление (имя профиля, скорость/итоги, тик
   только при живом экране, тап → приложение), QS-плитка, автозапуск с boot,
   шорткаты/интенты. Дёшево и снимает половину вопросов «оно включено?».
4. **Смена сети**: ранжирование транспортов с грейсом для «losing», переотправка DNS
   в ядро на каждом изменении линка и очистка при стопе, `setUnderlyingNetworks` на
   старых API — предсказуемый реконнект вместо «интернет пропал».
5. **Персистентность выбора и откат**: выбранный прокси в группе хранится per-profile
   (переживает рестарт и смену профиля), переключение дебаунсится и откатывается при
   ошибке; у auto-групп видно, какой узел реально используется.
6. **Ошибка = причина + действие**: типизированные сбои с одной человеческой строкой
   и кнопкой («профиль не сохранён → Edit», «нет профиля → Profiles», «VPN-конфиг
   изменён → Restart»), без стектрейсов.

### Среднее
7. Дисциплина тестов задержки: тест только текущей группы/прокси, пул с лимитом,
   pending на узле, отмена при смене профиля, пересортировка после теста, таймаут —
   пусто/Timeout, не ломающий сортировку.
8. Эргономика списка: табы групп + запоминание последней + scroll-to-selected;
   персистентные плотность/сортировка/стиль. Поиск по прокси не нужен, пока узлов
   <200, scroll-to-selected — обязателен.
9. Карточка профиля как статус-объект (used/total/срок/«N ago», скрытие пустых
   полей), авто-обновление с минимумом 15 мин, перепланирование планировщика на
   boot/смену времени и таймзоны, «Update all» с прогрессом, валидация редактора и
   подтверждение выхода без сохранения.
10. Очередь сообщений вместо спама тостами: дедуп, приоритет ошибок, лимит видимых,
    действие в карточке, свайп.
11. Разделение «сессионный override» / «постоянная настройка» с явной подписью —
    ровно как правило про смену режима на сессию.

### Низкое
12. Компонуемый дашборд-грид (скорость, donut трафика, режим, быстрые переключатели
    TUN/VPN/system-proxy, exit-IP, память) — после того как базовый экран стабилен.
13. Плотность/сетка/стиль иконок, отдельные раскладки mobile/desktop, focus для TV.
14. Логи: экспорт в файл, поиск, пауза авто-скролла, список файлов + «удалить всё» с
    подтверждением.

## Чего у них НЕТ
Глобального «тест всех групп» и поиска по прокси (тест только текущая группа/узел);
у CMFA нет онбординга — новичок видит пустой список профилей и получает тост с
действием при попытке старта; у FlClash разрешения (location для SSID, battery
optimization) остаются ручными шагами с подсказками. Копировать нечего — но и не
нужно: это как раз те места, где HydraBox может сделать лучше одной явной кнопкой.
