# Сценарии к перепрогону

Проверки, признанные VACUOUS или частичными на момент прогона: код формально проходит,
но доказано отсутствие издателя, а не отсутствие дефекта. Каждая строка обязана быть
повторена после указанной задачи. Пункт закрывается только содержательным прогоном.

| Сценарий | Проверка | Почему VACUOUS сейчас | Перепрогон после |
|---|---|---|---|
| M07 | число `NETWORK` и `REBIND` совпадает с прогоном до задачи | прогона «до» не существует: 20 задач уже смержены. Записываются абсолютные числа как новая базовая линия | `HB-RW-018` |

## Закрыто

- **M03** — «нет `runtime.stop.unconfirmed`»: закрыт по итогам `HB-RW-032-FIX-2` (DEVICE-2).
  Содержательный прогон: издатель теперь есть (`CoreRuntimeService.handleControllerEvent`
  обрабатывает `runtime.stop.unconfirmed`, `android/app/src/main/kotlin/io/hydrabox/client/runtime/CoreRuntimeService.kt:1838`).
  Во всех стоп-циклах сессии (A1, прогоны a1/a1b/a1c, ~40 остановок) — 0 вхождений строки.

## Новые сценарии (дефекты, найденные при приёмке DEVICE-2)

| Сценарий | Проверка | Наблюдение | Перепрогон после |
|---|---|---|---|
| A1-post-ready-tap | тап по кнопке подключения в окне ~2.4–3.1 с после `READY` должен останавливать/подключать | 6/6 тапов в окне 2.4–3.1 с после `READY` проглочены (циклы 2–10); тапы позже ≥4.7 с — работают. Исключение: цикл 1 (+2.7 с) сработал. Проглатывание — потеря события, а не задержка: cg последователен, повторного события нет | наряд тимлида |
| A1-spontaneous-restart | после `STOP stage=released` без тапа не появляется `CONNECT` (в т.ч. через минуты) | runtime воскресает без пользователя: стартовые состояния прогонов a1/a1b (через ~2–4 мин после пользовательского стопа) и `cg 21→27, rg→9` за ~105 с после c10 a1c. Прямые строки CONNECT не сняты (буфер очищен); контрольное окно 3 мин после чистого стопа — чистое, триггер не установлен | наряд тимлида |
