# Bugfix: экран добавления подписки мелькает на холодном старте

**Date:** 2026-09-15
**Repo:** HydraBox2
**Status:** spec, код не менялся

## Current behavior

При холодном запуске приложения, когда подписка уже установлена, примерно на секунду
показывается онбординг-шаг «добавьте подписку», и только потом открывается обычный экран.

Механика (проверено по коду):

1. `RuntimeControlActivity.onCreate` до первого кадра синхронно читает только настройки:
   `stored = stored.copy(legalAccepted = …)` — с комментарием, что это сделано именно для
   того, чтобы не рисовать онбординг человеку, который его давно прошёл
   (`platform/android/src/androidMain/kotlin/io/hydrabox/platform/android/RuntimeControlActivity.kt:318-324`).
2. Начальная модель — `AppReadModel(runtime = stoppedSnapshot())`, где `sources = emptyList()`.
3. Порог онбординга считается от источников: `hasSources = sources.isNotEmpty()`,
   `onboardingComplete = legalAccepted && hasSources`
   (`core/projection/src/commonMain/kotlin/io/hydrabox/core/projection/ScreenState.kt:290,293`).
4. Первый кадр: `legalAccepted = true`, `sources = []` → `onboardingComplete = false` →
   `OnboardingFlow` со шагом `SUBSCRIPTION` (`ui/app/src/commonMain/kotlin/io/hydrabox/ui/app/HydraApp.kt:99-108`).
5. `refresh()` читает stored-модель асинхронно на `reader` executor и приходит через
   ~0.3–1 с (открытие БД → `summaries()` → `catalogs()` → парсинг). Кэш каталогов
   (`AppStore.kt:521`) на холодном старте пуст, поэтому прогрева нет.

Итог: гонка «первый кадр против первого чтения хранилища» закрыта для `legalAccepted`,
но не закрыта для факта наличия подписок.

## Expected behavior

При наличии сохранённых подписок экран «добавьте подписку» SHALL NOT показываться ни на
одном кадре — ни на первом, ни до завершения чтения хранилища.

## Unchanged behavior

- Онбординг всё так же обязателен, когда подписок действительно нет (первый запуск и
  случай, когда последняя подписка удалена).
- Порядок шагов онбординга (приветствие → условия → подписка) не меняется.
- Чтение хранилища остаётся асинхронным: никакой синхронной загрузки каталогов до
  `setContent` (иначе ANR на холодном старте).

## Root cause

Порог онбординга опирается на `sources.isNotEmpty()`, а `sources` заполняется только
асинхронным `refresh()`. Дешёвый синхронный признак «в хранилище есть записи подписок»
на первом кадре не читается, хотя для `legalAccepted` такой приём уже применён.

## Fix plan (черновик, ждёт одобрения)

1. Добавить в модель чтения признак готовности/наличия: `sourcesKnown: Boolean` +
   число сохранённых записей, прочитанное в `onCreate` тем же синхронным приёмом, что и
   `legalAccepted` (только таблица записей, без парсинга каталогов — `AppStore.records()`).
2. Порог онбординга считать так: если хранилище ещё не читалось — от синхронно прочитанного
   наличия записей; после `refresh()` — от `sources`.
3. Убедиться, что удаление последней подписки по-прежнему возвращает онбординг
   (после `refresh()` признак обновляется, «залипшего» `true` быть не должно).

Альтернативы и почему не они:

- отдельный splash-экран до первого чтения — убирает мелькание, но добавляет задержку;
- хранить «онбординг пройден» в настройках — дублирует источник правды и расходится при
  удалении подписок;
- синхронный `refresh()` до `setContent` — ANR.

## Acceptance

- Юнит-тест проекции: модель «условия приняты, хранилище ещё не читалось, записи есть» →
  онбординг не показывается; «записей нет» → показывается.
- Юнит-тест: после удаления последней подписки онбординг возвращается.
- Живая проверка: холодный старт на устройстве с установленной подпиской — экран
  добавления подписки не появляется (screenrecord/logcat).
