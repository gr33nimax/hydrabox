# Быстрая спека: обновление как загрузка браузера

Замена собственного механизма скачивания APK на системный `DownloadManager`.

## Requirements

- FR-1: когда проверка нашла обновление, загрузка начинается **сама**, без нажатия «установить».
- FR-2: прогресс загрузки виден в шторке системным уведомлением — так же, как при скачивании APK из браузера.
- FR-3: по завершении нажатие на уведомление в шторке запускает системный установщик.
- FR-4: скачанный файл остаётся в общей папке «Загрузки» под именем с версией.
- FR-5: приложение не ведёт собственной загрузки и не хранит её хода: загрузку ведёт `DownloadManager`, а состояние (идёт/готово/ошибка) спрашивается у него при каждом обращении. Само приложение помнит только идентификатор загрузки.
- FR-6: перед установкой из интерфейса приложения файл проверяется: sha256 из подписанного манифеста и сертификат APK.
- FR-7: если проверка не прошла, приложение сообщает причину и не предлагает установку.
- NFR-1: загрузка переживает смерть процесса приложения (её ведёт система).
- NFR-2: приложение не запрашивает доступ к хранилищу и не показывает файл через свои URI.

## Design

**Загрузка.** `UpdateClient.startDownload(context, manifest)` строит `DownloadManager.Request`:

- адрес — `manifest.apkUrl`; MIME `application/vnd.android.package-archive`;
- назначение — `Environment.DIRECTORY_DOWNLOADS`, имя `hydrabox-<versionName>.apk`;
- `setNotificationVisibility(VISIBILITY_VISIBLE_NOTIFY_COMPLETED)` — прогресс и «готово» в шторке;
- `setAllowedOverMetered(true)`, `setAllowedOverRoaming(false)`.

**Состояние.** `UpdateClient.apkState(context, manifest)` спрашивает `DownloadManager.query` по сохранённому идентификатору загрузки и отвечает одним из: `Missing`, `Downloading(progress)`, `Ready(uri)`, `Failed(reason)`. Идентификатор — единственное, что приложение помнит само (он невыводим снаружи); идёт ли загрузка, сколько скачано и где файл — всё это спрашивается у системы каждый раз. Идентификатор привязан к версии: находка новой версии не показывает файл предыдущей.

**Проверка.** `UpdateClient.verify(context, manifest, id)` читает поток через `ContentResolver` (URI выдаёт система, доступ к хранилищу не нужен), считает sha256 и сравнивает с манифестом. Сертификат здесь не пересчитывается: подпись при установке проверяет сам Android, а хеш — это то, что связывает скачанные байты с подписанным документом.

**Установка.** `UpdateClient.installIntent(context, manifest)` берёт `getUriForDownloadedFile` и отдаёт `ACTION_VIEW` с флагом чтения.

**Состояние на экране.** `UpdateSummary` получает `downloading: Boolean`; строка обновления показывает «качается» с версией, а по готовности предлагает установку. `installFault` переиспользуется для отказа проверки.

**Удаляется.** `UpdateClient.install/download/stage`, `UpdateInstallReceiver` и его запись в манифесте, загрузка в `cacheDir`, сессия `PackageInstaller`. Разрешение `REQUEST_INSTALL_PACKAGES` остаётся: установку из интерфейса инициирует приложение.

## Tasks

- TSK-1: `UpdateClient` — `startDownload`, `apkState`, `verify`, `installIntent`; удалить старый путь.
- TSK-2: `UpdateInstallReceiver` и его запись в манифесте удалить.
- TSK-3: `RuntimeControlActivity` — запуск загрузки сразу после находки; обработчик установки через проверку.
- TSK-4: `UpdateSummary.downloading` + тексты строки обновления (ru/en).
- TSK-5: тесты платформенного модуля на разбор имени файла и решение о состоянии.
- TSK-6: сборка и проверка на устройстве: прогресс в шторке, файл в «Загрузках», установка по нажатию.

## Acceptance

- AC-1: после находки обновления без дополнительных действий появляется системная загрузка с прогрессом в шторке.
- AC-2: по завершении файл `hydrabox-<версия>.apk` лежит в «Загрузках».
- AC-3: нажатие уведомления открывает установщик; установка проходит.
- AC-4: при подменённом файле приложение показывает отказ проверки и не даёт установить из своего интерфейса.
- AC-5: `UpdateInstallReceiver` и код сессии установщика отсутствуют; сборка проходит.
